ชื่อโครงงาน (ชั่วคราว):
ระบบบริหารจัดการและเบิกจ่ายอุปกรณ์ IT พร้อมระบบพยากรณ์สต็อกด้วย Machine Learning (Intelligent IT Equipment Requisition System with Predictive Analytics)

🎯 วัตถุประสงค์หลักของระบบ
เพื่อพัฒนาระบบเบิก-คืนอุปกรณ์ IT ที่ลดขั้นตอนการทำงานของแอดมินให้เหลือเพียงขั้นตอนเดียว และนำข้อมูลการเบิกจ่ายมาประยุกต์ใช้กับโมเดล Machine Learning เพื่อพยากรณ์ล่วงหน้าว่าวัสดุสิ้นเปลืองจะหมดเมื่อใด รวมถึงนำเสนอข้อมูลสรุปผลในรูปแบบ Dashboard ที่รองรับปริมาณข้อมูลขนาดใหญ่ได้อย่างรวดเร็ว

⚙️ ฟีเจอร์หลักของการทำงาน (Core Features)
1. ระบบจัดการสิทธิ์และการเข้าใช้งาน (Authentication & RBAC)

เข้าสู่ระบบด้วยความปลอดภัยรูปแบบ JWT

แบ่งสิทธิ์การใช้งานเพียง 2 ระดับเพื่อความกระชับ:

User (พนักงานทั่วไป): สามารถทำรายการขอเบิก, ดูประวัติการเบิกของตนเอง และสแกนรับ-คืนอุปกรณ์

Admin (ฝ่าย IT): สามารถจัดการสต็อกอุปกรณ์, อนุมัติ/ปฏิเสธคำขอ (1-Step Approval) และดู Dashboard สรุปผลภาพรวม

2. ระบบจัดการคลังอุปกรณ์แบบไฮบริด (Hybrid Inventory Management)

รวมการจัดการอุปกรณ์ทุกประเภทไว้ในหน้าจอเดียว โดยใช้เงื่อนไข (Flag) is_consumable ในการแยกประเภทลอจิกการทำงาน:

สินทรัพย์ถาวร (เช่น โน้ตบุ๊ก, จอมอนิเตอร์): บังคับกรอก Serial Number, เมื่อเบิกแล้วจะมีสถานะค้างในระบบ และต้องมีการกดยืนยันหรือสแกนเพื่อ "คืนอุปกรณ์"

ของสิ้นเปลือง (เช่น หมึกพิมพ์, กระดาษ, เมาส์): ไม่มี Serial Number เมื่อคำขอได้รับการอนุมัติ ระบบจะตัดจำนวนสต็อก (Quantity) ทันทีโดยไม่ต้องมีการคืน

3. ระบบสแกน QR Code สำหรับรับ-คืนอุปกรณ์

สร้าง QR Code ประจำตัวอุปกรณ์ (สำหรับสินทรัพย์ถาวร) หรือประจำคำขอเบิก เพื่อให้พนักงานหรือแอดมินใช้กล้องสแกนยืนยันการรับหรือคืนของได้ทันที ลดความผิดพลาดจากการกรอกข้อมูลด้วยมือ

🌟 จุดเด่นเชิงวิศวกรรมซอฟต์แวร์และวิทยาการคอมพิวเตอร์ (Core Tech สำหรับทำคะแนน)
1. ระบบพยากรณ์สต็อกคงเหลือ (Predictive Analytics)

นำประวัติการเบิกใช้วัสดุสิ้นเปลืองมาเทรนโมเดล Machine Learning เพื่อพยากรณ์ความน่าจะเป็นและระยะเวลาที่ของในสต็อกจะหมด (Stock Depletion Forecast) ช่วยให้ฝ่าย IT สามารถวางแผนจัดซื้อล่วงหน้าได้อย่างแม่นยำ

2. แดชบอร์ดสรุปผลและสถาปัตยกรรมข้อมูลประสิทธิภาพสูง (High-Performance Dashboard)

ออกแบบระบบจัดการแสดงผลข้อมูลรายการเบิก-คืนปริมาณมหาศาล โดยใช้ AG-Grid ในการจัดการตารางบนหน้าเว็บ เพื่อให้เรนเดอร์ข้อมูลได้รวดเร็ว

ใช้วิธีการทำ SQL Aggregation จากฝั่ง PostgreSQL เพื่อประมวลผล จัดกลุ่ม และคำนวณผลสรุปต่างๆ จากฝั่งฐานข้อมูลโดยตรง ก่อนส่งข้อมูลที่ย่อยแล้วมาแสดงเป็นกราฟสถิติผ่าน ApexCharts (ลดปัญหาคอขวดของการดึงข้อมูลดิบมาคำนวณที่ฝั่ง Frontend)

🛠️ เครื่องมือและเทคโนโลยีที่ใช้ (Tech Stack)
Frontend: Angular 21, HTML, CSS, TypeScript
Backend: Node.js
Database: PostgreSQL

ขอบเขตของโครงงาน (Scope)


ผู้ใช้งาน 2 ระดับ: พนักงานทั่วไป (User) และ ฝ่าย IT (Admin) 


ฟีเจอร์หลัก: ระบบเบิก-คืน, อนุมัติ 1-Step Approval, ระบบคลัง, แดชบอร์ด 

เทคโนโลยีที่ใช้ (Tech Stack):


Frontend: Angular 21, ApexCharts, AG-Grid 


Backend & DB: Node.js, PostgreSQL (ทำ Data Aggregation) 

Slide 5: การวิเคราะห์ความต้องการ (Requirements)


Input (ข้อมูลนำเข้า): ข้อมูลพนักงาน, คลังอุปกรณ์, คำขอเบิก, สแกน QR Code, และประวัติการเบิกย้อนหลัง 


Process (การประมวลผล): จัดการสิทธิ์เข้าถึง, ลอจิกสต็อกแบบไฮบริด, ทำ SQL Aggregation, และพยากรณ์สต็อก (ML) 


Output (ข้อมูลนำออก): แดชบอร์ดกราฟ/ตาราง, ผลพยากรณ์ระยะเวลาของหมด, ภาพ QR Code ใหม่, และสถานะการอนุมัติ 

Slide 6: การออกแบบและการพัฒนา (Design & Implementation)


สถาปัตยกรรม: Client-Server แยกฝั่ง Frontend (Angular) และ Backend (Node.js) อย่างชัดเจน 


ฐานข้อมูล: ออกแบบ ER Diagram บน PostgreSQL และเขียนสคริปต์ SQL Aggregation ลดภาระข้อมูล 


Flowchart: เขียนลอจิกการทำงานแยกกันระหว่าง "สินทรัพย์ถาวร" (ต้องสแกนคืน) และ "ของสิ้นเปลือง" (ตัดสต็อกทันที) 


Machine Learning: จัดเตรียมข้อมูล (Data Preprocessing) และเทรนโมเดลเพื่อพยากรณ์ 

Slide 7: การทดสอบและประเมินผล (Testing & Evaluation)


System Testing: ทดสอบการทำงานของ API ข้ามส่วนกับระบบสแกน QR Code 


Performance Testing: ทดสอบความเร็วการโหลดของ Dashboard เมื่อข้อมูลมีจำนวนมาก 


Model Evaluation: ประเมินความแม่นยำของโมเดลพยากรณ์ ML ด้วยหลักสถิติ 


UAT (User Acceptance Testing): จำลองการใช้งานจริงของฝั่ง User และ Admin
